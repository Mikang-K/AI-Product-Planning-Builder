# AI Product Planning Agent 프로젝트 기획서 요약

## 1. 프로젝트 개요

본 프로젝트는 사용자의 초기 아이디어를 입력받아, 단순한 추천이나 조언을 넘어 **제품 기획 프로세스를 자동으로 수행하는 AI 에이전트 시스템**을 구축하는 것을 목표로 한다.

초기 단계에서는 **기획자 에이전트**를 중심으로 MVP 범위 정의, 핵심 가정 도출, 사용자 시나리오 작성, 검증 실험 설계, PRD 초안 생성까지 수행한다.

추후에는 **개발 에이전트**, **검증 에이전트**를 추가하여 세 에이전트가 협업하고, 최종적으로는 아이디어 입력만으로도 **프로덕트 레벨의 산출물**을 자동 생성하는 멀티 에이전트 시스템으로 확장한다.

---

## 2. 프로젝트 목표

### 핵심 목표

사용자의 아이디어를 실제 제품화 가능한 기획 산출물로 변환하는 AI 에이전트 시스템을 만든다.

### 세부 목표

- 아이디어를 구조화된 제품 기획 요소로 변환
- 핵심 사용자, 문제, 해결책, 차별점 도출
- 불확실한 가정과 리스크 추적
- MVP 범위 자동 축소
- 검증 가능한 실험 설계
- PRD 초안 자동 생성 및 업데이트
- 추후 개발/검증 에이전트와 협업 가능한 구조 설계

---

## 3. 핵심 컨셉

### 한 줄 설명

> 아이디어를 입력하면 AI 기획자가 PM처럼 분석하고, MVP로 줄이고, 검증 실험과 PRD까지 만들어주는 에이전트.
> 

### 핵심 차별점

일반 LLM은 사용자의 질문에 답변을 제공하지만, 본 프로젝트의 에이전트는 다음과 같은 차이를 가진다.

- 단순 추천이 아니라 **기획 프로세스 수행**
- 아이디어를 **구조화된 산출물**로 변환
- 부족한 정보를 스스로 질문
- 핵심 가정을 추적하고 우선순위화
- 기능을 추가하는 것이 아니라 MVP로 축소
- 다음 행동 가능한 실험 계획까지 제안
- 사용자의 답변에 따라 PRD를 지속적으로 갱신

---

## 4. 타깃 사용자

### 1차 타깃

- 사이드 프로젝트를 준비하는 개인 개발자
- 초기 스타트업 창업자
- 제품 아이디어를 빠르게 검토하고 싶은 기획자
- 서비스 기획을 배우는 주니어 PM/PO
- 해커톤 참가자

### 사용자의 주요 문제

- 아이디어는 있지만 제품으로 구체화하기 어렵다.
- 기능 욕심이 많아 MVP 범위를 줄이지 못한다.
- 무엇을 먼저 검증해야 할지 모른다.
- PRD나 기획 문서를 작성하는 데 시간이 오래 걸린다.
- 시장성, 구현 가능성, 사용자 니즈를 균형 있게 판단하기 어렵다.

---

## 5. 전체 시스템 비전

최종적으로는 세 가지 에이전트가 협업하는 구조를 지향한다.

```
사용자 아이디어 입력
        ↓
기획자 에이전트
        ↓
개발 에이전트
        ↓
검증 에이전트
        ↓
프로덕트 레벨 산출물 생성
```

### 에이전트별 역할

| 에이전트 | 주요 역할 |
| --- | --- |
| 기획자 에이전트 | 아이디어 구조화, MVP 정의, PRD 생성 |
| 개발 에이전트 | 기술 구조 설계, 구현 난이도 평가, 개발 태스크 분해 |
| 검증 에이전트 | 리스크 검토, 실험 설계, 산출물 품질 평가 |

---

## 6. 1차 MVP 범위: 기획자 에이전트

초기 버전에서는 기획자 에이전트만 구현한다.

### 입력

사용자가 한 줄 또는 짧은 문장으로 제품 아이디어를 입력한다.

예시:

```
혼자 공부하는 사람들을 위한 AI 스터디 플래너
```

### 처리 과정

기획자 에이전트는 다음 단계를 수행한다.

1. 아이디어 구조화
2. 부족한 정보 질문 생성
3. 핵심 가정 도출
4. MVP 범위 축소
5. 사용자 시나리오 작성
6. 성공 지표 추천
7. 검증 실험 설계
8. PRD 초안 생성

### 출력 산출물

- 아이디어 진단 카드
- 정보 보완 질문
- 핵심 가정 보드
- MVP 범위
- 제외할 기능 목록
- 사용자 시나리오
- 성공 지표
- 검증 실험 계획
- PRD 초안

---

## 7. 기획자 에이전트 주요 기능

## 7.1 아이디어 구조화

사용자의 아이디어를 제품 기획 요소로 분해한다.

### 출력 항목

- 제품 한 줄 설명
- 타깃 사용자
- 해결하려는 문제
- 기존 대안
- 핵심 가치 제안
- 차별화 포인트
- 예상 수익화 가능성
- 구현 난이도
- 가장 위험한 가정

---

## 7.2 정보 가치 높은 질문 생성

에이전트가 아이디어를 더 정확히 판단하기 위해 필요한 질문을 생성한다.

### 원칙

- 질문은 너무 많지 않게 제한한다.
- 가장 정보 가치가 높은 질문 3개를 우선 제시한다.
- 질문의 목적을 함께 설명한다.

### 예시

```
1. 주요 타깃은 학생인가요, 직장인인가요?
   - 이유: 타깃에 따라 기능, 메시지, 수익 모델이 달라집니다.

2. 사용자가 현재 쓰고 있는 대체 서비스는 무엇인가요?
   - 이유: 기존 대안과의 차별점을 파악하기 위해 필요합니다.

3. 사용자가 가장 자주 실패하는 지점은 계획 수립인가요, 실행 지속인가요?
   - 이유: 제품의 핵심 기능 방향을 결정하는 질문입니다.
```

---

## 7.3 핵심 가정 보드

아이디어가 성공하기 위해 반드시 참이어야 하는 가정을 정리한다.

### 가정 분류 기준

- 중요도
- 불확실성
- 검증 난이도
- 검증 방법

### 예시

| 가정 | 중요도 | 불확실성 | 검증 방법 |
| --- | --- | --- | --- |
| 사용자는 공부 계획을 직접 짜기 귀찮아한다 | 높음 | 중간 | 사용자 인터뷰 |
| AI가 만든 계획을 신뢰할 것이다 | 높음 | 높음 | 랜딩페이지 테스트 |
| 매일 알림을 받으면 재방문할 것이다 | 중간 | 높음 | 7일 프로토타입 테스트 |

### 우선순위 원칙

가장 먼저 검증해야 할 것은 **중요도가 높고 불확실성도 높은 가정**이다.

---

## 7.4 MVP 자동 축소

사용자가 제안한 기능 또는 아이디어에서 핵심 검증에 필요한 최소 기능만 남긴다.

### 수행 내용

- 핵심 문제와 직접 관련 없는 기능 제거
- 구현 비용 대비 검증 가치가 낮은 기능 제외
- MVP 필수 기능 3~5개로 축소
- 제외된 기능의 이유 기록

### 예시

```
## MVP에 포함할 기능

1. 목표 입력
2. AI 주간 계획 생성
3. 매일 완료 체크

## MVP에서 제외할 기능

- 친구 추가
- 랭킹
- 커뮤니티
- 결제

## 제외 이유

현재 단계에서 검증해야 할 핵심은 “AI가 만든 계획을 사용자가 실제로 따르는가”입니다.
커뮤니티와 랭킹은 지속 사용 단계에서 중요할 수 있지만, 초기 핵심 가정 검증과는 거리가 있습니다.
```

---

## 7.5 사용자 시나리오 생성

제품 기능을 단순 목록이 아니라 실제 사용자 흐름으로 변환한다.

### 포함 항목

- 사용자 배경
- 문제 상황
- 제품 사용 계기
- 핵심 사용 흐름
- 기대되는 변화
- 이탈 가능 지점

### 예시

```
지민은 토익 공부를 매번 3일 하다 포기하는 직장인이다.

지민은 앱에 “한 달 안에 토익 750점 달성”이라는 목표를 입력한다.
AI는 하루 40분짜리 현실적인 주간 계획을 생성한다.

3일째 지민이 미션을 건너뛰자, 앱은 기존 계획을 비난하지 않고 자동으로 줄여준다.
지민은 “실패했다”가 아니라 “계획이 조정됐다”고 느끼며 다시 공부를 이어간다.
```

## 7.6 성공 지표 추천

제품의 성공 여부를 판단할 수 있는 지표를 제안한다.

### 지표 예시

- D1 재방문율
- D7 재방문율
- 핵심 기능 사용률
- 계획 완료율
- 사용자 직접 수정률
- AI 추천안 선택률
- 실험 신청 전환율

### 원칙

단순 가입자 수보다 **핵심 가치 경험 여부를 보여주는 지표**를 우선한다.

## 7.7 검증 실험 설계

핵심 가정을 빠르게 검증할 수 있는 실험을 설계한다.

### 출력 항목

- 검증할 가정
- 실험 방법
- 대상 사용자
- 기간
- 성공 기준
- 실패 기준
- 다음 액션

### 예시

```
## 검증 실험

### 검증할 가정

사용자는 AI가 만든 공부 계획에 관심을 가진다.

### 실험 방법

랜딩페이지를 만들고 “AI 주간 공부 계획 받아보기” 신청 폼을 배치한다.

### 기간

3일

### 성공 기준

방문자 100명 중 10명 이상 신청

### 실패 기준

신청률 3% 미만

### 다음 액션

- 성공 시: 간단한 계획 생성 MVP 개발
- 실패 시: 타깃 사용자 또는 메시지 재정의
```

## 7.8 PRD 자동 생성 및 업데이트

기획자 에이전트는 최종적으로 PRD 초안을 생성한다.

### PRD 구성

```
# PRD

## 1. 제품 개요
## 2. 문제 정의
## 3. 타깃 사용자
## 4. 핵심 가치 제안
## 5. 사용자 시나리오
## 6. MVP 범위
## 7. 기능 요구사항
## 8. 제외할 기능
## 9. 성공 지표
## 10. 핵심 가정
## 11. 검증 실험 계획
## 12. 리스크
## 13. 향후 확장 방향
```

### 업데이트 방식

사용자가 질문에 답하거나 조건을 변경하면 PRD의 관련 섹션을 자동으로 갱신한다.

예시:

```
사용자: 타깃은 학생보다 직장인이야.
```

에이전트는 다음 항목을 함께 수정한다.

- 타깃 사용자
- 문제 정의
- 사용자 시나리오
- 핵심 기능
- 성공 지표
- 마케팅 메시지
- 검증 실험 대상

---

## 8. 추후 확장: 개발 에이전트

개발 에이전트는 기획자 에이전트가 만든 PRD를 기반으로 실제 구현 가능한 개발 산출물을 생성한다.

### 주요 역할

- 기술 요구사항 분석
- 프론트엔드/백엔드 구조 설계
- 데이터 모델 설계
- API 명세 작성
- 개발 태스크 분해
- 구현 난이도 평가
- 기술 리스크 식별
- MVP 개발 일정 제안

### 예상 산출물

- 기술 설계서
- 시스템 아키텍처
- ERD 초안
- API 명세
- 프론트엔드 페이지 구조
- 백엔드 기능 목록
- 개발 태스크 보드
- 우선순위별 구현 계획

### 기획자 에이전트와의 협업 방식

```
기획자 에이전트: MVP 기능 정의
        ↓
개발 에이전트: 구현 가능성 검토
        ↓
기획자 에이전트: 기능 범위 재조정
        ↓
개발 에이전트: 개발 태스크 생성
```

---

## 9. 추후 확장: 검증 에이전트

검증 에이전트는 기획 및 개발 산출물의 품질과 리스크를 평가한다.

### 주요 역할

- 기획 논리 검증
- 핵심 가정 검토
- 사용자 가치 검증
- 기능 과잉 여부 판단
- 실험 설계 타당성 평가
- 개발 범위 리스크 검토
- PRD 품질 평가
- 출시 전 체크리스트 생성

### 예상 산출물

- 리스크 분석 리포트
- 가정 검증 우선순위
- 실험 설계 리뷰
- PRD 품질 점수
- MVP 범위 적정성 평가
- 출시 전 체크리스트
- 개선 권고안

### 기획자 에이전트와의 협업 방식

```
기획자 에이전트: PRD 생성
        ↓
검증 에이전트: 논리, 리스크, 실험 타당성 평가
        ↓
기획자 에이전트: 피드백 반영
        ↓
검증 에이전트: 최종 승인 또는 수정 요청
```

---

## 10. 멀티 에이전트 협업 구조

최종 시스템은 다음과 같은 협업 루프를 가진다.

```
1. 사용자 아이디어 입력
2. 기획자 에이전트가 제품 기획 초안 생성
3. 검증 에이전트가 기획 리스크 및 논리 검토
4. 기획자 에이전트가 PRD 수정
5. 개발 에이전트가 기술 설계 및 구현 태스크 생성
6. 검증 에이전트가 개발 범위와 제품 목표의 정합성 검토
7. 세 에이전트가 최종 산출물 패키지 생성
```

## 15. 성공 기준

### MVP 성공 기준

- 사용자가 한 줄 아이디어만 입력해도 PRD 초안이 생성된다.
- 핵심 가정과 MVP 범위가 명확히 제시된다.
- 사용자가 “무엇을 먼저 검증해야 하는지” 알 수 있다.
- 일반 LLM 답변보다 구조화된 기획 산출물을 제공한다.
- 사용자의 추가 답변에 따라 산출물이 갱신된다.

### 장기 성공 기준

- 기획, 개발, 검증 산출물이 하나의 흐름으로 연결된다.
- 아이디어 입력부터 개발 태스크 생성까지 자동화된다.
- 세 에이전트가 서로 피드백하며 산출물 품질을 개선한다.
- 사용자는 단순 답변이 아니라 실제 제품 제작에 필요한 패키지를 얻는다.

## 16. 핵심 가치 요약

이 프로젝트의 핵심은 AI가 “좋은 아이디어네요”라고 말하는 것이 아니다.

AI가 사용자의 아이디어를 받아 다음 과정을 수행하는 것이다.

```
아이디어를 구조화하고
→ 부족한 정보를 질문하고
→ 위험한 가정을 찾고
→ MVP로 줄이고
→ 실험으로 검증하고
→ PRD로 문서화하고
→ 개발 가능한 태스크로 변환하고
→ 검증 에이전트가 다시 점검한다.
```

따라서 이 프로젝트는 단순한 LLM 기반 기획 도구가 아니라,

**제품 제작 프로세스를 자동화하는 멀티 에이전트 기반 Product Builder**를 지향한다.
